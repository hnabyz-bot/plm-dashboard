# 화면 함수와 합성 검사 계약

`executive-app.js`의 최초 로드와 수동 재확인은 같은 검증·반영 경로를 사용한다.

- 검증 전 자료는 표시 상태에 반영하지 않는다.
- 필수 구조 또는 기준일·생성시각이 맞지 않는 묶음은 거부한다.
- 첫 성공 반영에서 저장한 관심 선택을 불러온다. 초기 실패 뒤 재시도도 동일하다.
- 이후 사용자가 바꾼 관심 선택은 재확인 과정에서 덮어쓰지 않는다.
- 인허가 필터 항목은 공통 함수로 재구성해 중복 표시를 방지한다.

## 합성 검사 범위

Node 검사는 48개다: 기존 모듈 회귀 34개, 주소 계약 5개, 초기화·복구 계약 9개.
초기화 검사는 정상 입력, 구조·기준일·생성시각 불일치, 첫 요청 실패 뒤 복구, 저장 선택 유지와 인허가 필터 중복 방지를 합성 입력으로 확인한다.
Python 계약 검사는 11개다: 별도 읽기 서버 6개, 기존 로컬 실행기 서버 5개. 고정 읽기 경로와 쓰기 거부 등의 응답 계약을 격리된 입력으로 확인한다.

기존 shell·batch·macOS 실행기가 사용하는 `scripts/local-dashboard-server.py`도 집계5경로 GET/HEAD를 지원한다. query는 전달하지 않고 집계 리다이렉트는 차단하며 `/runtime/dashboard`는404로 유지한다. 기존 `/op` 읽기 동작과 upstream 선택 설정은 변경하지 않았다. 신규 검사는 원문 보존·HEAD 본문 없음과 길이·query 격리·미지원 경로와 쓰기 비전달·리다이렉트 차단·기존 `/op` 보존을 확인한다.

이 검사는 실제 업무 자료의 정확성이나 새 환경 전체 재현을 입증하지 않는다.
